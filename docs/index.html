Eclipse render worker

Lend a machine with a graphics card to an Eclipse studio. It runs one small container. The studio connects to it with one key, sends a render job, and takes the finished video back.

1. The key RunPod Linux server Windows PC What to send back Let an AI agent do it Remove it

What it opens on your machine: one port, answered by a door that accepts a single key. No password works, and it does not forward connections to anything else.

What the key allows: the studio can copy files into the container and run programs inside it. That is how a render job works. Treat it as lending the studio that container, with your card and as much processor as Docker gives it.

What it cannot do: see or change files on your machine outside its own storage folder. The container does have normal internet access, like any other container.

Which way the connection goes: the studio calls your machine. The worker starts no connection of its own.

1. The key from the studio

The studio sends you one line that starts with ssh-ed25519. It is a public key, so it is safe to send in a chat. Paste it here and every command on this page fills in. Nothing you type leaves this page.

RunPod

  1. Deploy a GPU pod. Pick a card that has a video encoder, for example an RTX 4090, RTX A5000, L4 or L40S. The A100 and H100 have no video encoder.
  2. Use these settings for the pod:
    SettingValue
    Container imageghcr.io/vilkam/eclipse-remote-worker:0.1.0
    Expose TCP ports22 (TCP, not HTTP)
    Expose HTTP portsleave empty
    Start commandleave empty
    Volume mount path/workspace, 20 GB is enough
    Environment variableECLIPSE_WORKER_KEY = the studio key
  3. Set the key when you create the pod. Do not save it into a shared template.
  4. When the pod runs, open its Logs and find the line eclipse-worker: host key SHA256:….
  5. Open Connect and read the address under Direct TCP ports, the one that leads to port 22. It looks like 203.0.113.7:41822.
  6. Send both to the studio.
The outside port changes when a pod restarts, so send the new address again after a restart. When you are done, terminate the pod. A stopped pod keeps its storage, with any footage still on it, and keeps costing money for that storage.

Linux server

You need Docker and, for a card, the NVIDIA driver with the NVIDIA container toolkit. This checks that Docker can see the card:

docker run --rm --gpus all --entrypoint nvidia-smi ghcr.io/vilkam/eclipse-remote-worker:0.1.0

With Tailscale (recommended)

The port then exists only on your Tailscale address. Nothing changes on your router or firewall. Install Tailscale, then share this one machine with the studio's Tailscale account from the Tailscale admin page (Machines → Share). A share covers the whole machine, not only the worker's port.

docker run -d --name eclipse-worker --restart unless-stopped --gpus all \
  -p "$(tailscale ip -4):2222:22" -v eclipse-worker:/workspace \
  -e ECLIPSE_WORKER_KEY="PASTE-THE-STUDIO-KEY" \
  ghcr.io/vilkam/eclipse-remote-worker:0.1.0
docker logs eclipse-worker

With a public address

Use this only if the server already has a public address. Allow port 2222 from the studio's address only, in the provider's firewall. Docker's published ports are not filtered by ufw, so a ufw rule alone does not restrict it.

docker run -d --name eclipse-worker --restart unless-stopped --gpus all \
  -p 2222:22 -v eclipse-worker:/workspace \
  -e ECLIPSE_WORKER_KEY="PASTE-THE-STUDIO-KEY" \
  ghcr.io/vilkam/eclipse-remote-worker:0.1.0
docker logs eclipse-worker

On a machine without a card, leave out --gpus all. It then lends processor cores only.

Windows PC

  1. Install a current NVIDIA driver, Docker Desktop (with the WSL 2 engine, its default) and Tailscale.
  2. In the Tailscale admin page, share this one PC with the studio's Tailscale account (Machines → Share). The studio can then reach this PC, and not the rest of your network. A share covers the whole PC, so anything else on it that listens on every address is reachable by the studio too.
  3. In PowerShell:
$ts = (tailscale ip -4)
docker run -d --name eclipse-worker --restart unless-stopped --gpus all -p "${ts}:2222:22" -v eclipse-worker:/workspace -e "ECLIPSE_WORKER_KEY=PASTE-THE-STUDIO-KEY" ghcr.io/vilkam/eclipse-remote-worker:0.1.0
docker logs eclipse-worker

The worker is then reachable on the PC's Tailscale address only. To confirm, this must fail from another device on your home network: Test-NetConnection YOUR-PC-LAN-ADDRESS -Port 2222.

If the container does not start after a reboot, Tailscale was not up yet when Docker started. Run docker start eclipse-worker.

What to send back

The studio needs two things. Both are safe to send in a chat.

WhatWhere you find it
Address and portRunPod: the direct TCP address. Otherwise your Tailscale address (tailscale ip -4) or public address, with port 2222.
Host keyThe line eclipse-worker: host key SHA256:… in docker logs eclipse-worker or the pod's log. It lets the studio be sure it reached your worker and nobody in between.

On the studio side, connecting is then two commands:

python -m harness.remote add NAME ADDRESS:PORT --fingerprint SHA256:…
python -m harness.remote enable NAME

The first one checks the machine and reports its cores, memory, cards, whether the card can encode video, and the speed of the link.

What it sees, and how to remove it

  • While a clip renders, its footage and the fonts and style files it needs are on your machine, inside the worker's storage. Whoever controls the machine can see them.
  • A job's own folder is deleted when the job ends. Footage kept to avoid sending it twice is deleted by the worker itself about an hour after its last use. The studio deletes everything it stored when it disconnects.
  • You can stop lending the machine at any time. The studio then renders on its own machine instead.

To remove the worker and everything it stored:

docker rm -f eclipse-worker
docker volume rm eclipse-worker
docker rmi ghcr.io/vilkam/eclipse-remote-worker:0.1.0

On RunPod, terminate the pod. If you shared the machine over Tailscale, remove the share in the Tailscale admin page.

Image: ghcr.io/vilkam/eclipse-remote-worker:0.1.0. Its two source files are in the repository; the image holds no application code, fonts, models or credentials.
